# 再生塑料配方试配筛选（质检模型 + 最优改配求解 + 新增批次适用性核查）

面向再生塑料配方研究员与质检工程师的网页工具，包含两个相互独立的功能：

1. **试配求解**：录入原配方与各原料的上下限、锁定项后，在**合格概率 ≥ 0.7**
   的约束下，按 **先最少改变原料种数、再最小化总克数改变量** 的字典序求出最优试配方案；
   只有求解器**证明**无解才报无解，求解失败单独报告。
2. **新增批次适用性核查**：粘贴 20～200 行总重 1000 克的四料整数克数记录，以固定种子
   另行生成的 1000 条训练外参考配方为基准，按模型 float32 输入语义比较两组在五棵树
   各叶节点的占比，做 999 次联合置换检验；**仅当 p ≤ 0.05 才提示人工复核**，否则只报
   “未检出偏移”，**不做放行判断**。

## 技术栈与模型

- **FastAPI** 提供网页与 JSON API；**scikit-learn** 训练随机森林；**z3-solver** 求解。
- 质检模型：`RandomForestClassifier(n_estimators=5, max_depth=3, random_state=20241117)`，
  在固定种子生成的合成数据上训练（Dirichlet 采样的配方比例 + 含噪质检规则，阈值取中位数
  使类别均衡）。每次启动以同一种子重训，结果确定（自测第 1 项验证同种子重训一致）。
- 配方为 4 种原料的整数克数，总重 1000 克；模型输入为克数 ÷ 1000 的 **float32** 比例。

## 求解语义（与分类器严格一致）

- sklearn 树内部以 float32 特征与 float64 阈值比较。求解器把每个分裂条件
  `float32(g/1000) <= τ` 预计算为等价的**整数截断** `g <= K`（`app/model.py: cutoff_left`），
  因此 z3 中的约束与原分类器的实际阈值语义逐点一致（自测第 2 项对全部阈值 × 0–1000 克逐点核对）。
- 森林概率 = 5 片叶子概率（精确有理数）之和 / 5 ≥ 0.7，以精确有理数编码进 z3。
- 字典序优化用**两阶段**实现：先最小化改动种数，固定该最优值后再最小化总改动克数。
- 每份建议解出后**用原 sklearn 分类器复算概率**（float32 输入），未通过复核则按求解失败上报，
  绝不当作合格建议展示。
- 结果状态严格区分：`ok`（已证明最优）/ `infeasible`（z3 判定 unsat，即证明无解）/
  `invalid`（输入不合法）/ `solver_failure`（z3 unknown、超时或异常，**不**当作无解）。

## 新增批次适用性核查（`app/drift.py`）

### 基准参考集（训练外、固定种子）

- 以与训练种子 `20241117` **不同的固定种子 `20241118`** 另行生成 **1000 条参考配方**，
  与训练数据同属 Dirichlet 生成族（`alpha=[2.5, 2.0, 1.6, 1.2]`，即“熟悉的配方范围”），
  但通过最大余数法落为总重 1000 克的四料**整数克数**；训练样本是连续比例、参考集是
  整数配方，二者不重合。结果完全可复现（自测 9.1 核对同种子逐元素一致）。
- 启动时即把参考集按模型的 **float32 输入语义**预路由到五棵树的叶节点：
  `clf.apply((grams/1000).astype(float32))`，与训练/预测路径完全相同的
  float32 特征对 float64 阈值分裂比较。

### 统计量与置换检验

- **叶节点占比**：对每棵树的每个叶节点，分别统计参考组（1000 条）与批次组
  （20～200 行）落入该叶的样本占比。
- **统计量 T**：五棵树**所有叶节点**占比差的最大绝对值
  `max |批次占比 − 参考组占比|`；并列时按树下标、叶 id 升序取第一个，结果确定。
- **联合置换检验**：合并两组共 `1000+n` 个样本，保持批次组大小 `n` 不变，以固定种子
  `20241119` 做 **999 次**随机重分组并重算 T。整体 p 值取含观测值的无偏估计
  `p = (1 + #{T_perm ≥ T_obs}) / (1 + 999)`，最小为 1/1000。
- 结论只有两种：`p ≤ 0.05` → `review`（**提示人工复核**，并展示差异最大的树、叶节点
  id 及两组占比与占比差）；`p > 0.05` → `no_shift`（只报**未检出偏移**，明确声明
  **不构成放行判断**）。两种结论都附带统计量、p 值、样本量、置换次数与耗时。

### 输入校验（出错不出结论）

- 粘贴文本按行解析：每行须恰好 4 个整数克数（空格或逗号分隔），每个克数 ∈ [0, 1000]，
  每行总重恰为 1000 克；有效行数须在 20～200 行。空行、小数、非数字、负数、越界、
  总重不符、行数越界等都返回带行号的错误列表，**不产生任何统计结论**（响应中无 p 值）。
- 前端**编辑批次立即撤下旧报告**：核查区使用独立于求解区的 epoch + AbortController，
  任何编辑都会中止在途请求、清空结论区；迟到响应经序号比对后丢弃，**不会恢复旧报告**。
  原试配求解功能与该机制完全不受影响。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

### 本地开发

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 页面与交互

- 录入：4 种原料的原配方克数、各自下限/上限、锁定勾选；总重须为 1000 克。
- 「载入可行样例」「载入无解样例」：样例在服务启动时由真实模型 + 求解器**实测验证**后生成
  （`app/samples.py`），可行样例含锁定项，无解样例为上下限把配方逼入不合格区域的情形。
- **计算期间可随时修改**：任何输入修改会立即撤下旧建议（清空结果区）、中止在途请求；
  迟到的旧响应按请求序号（epoch）比对后直接丢弃，不会恢复显示（`app/static/index.html`）。
- 结果展示：合格概率（原分类器复算值）、逐原料改动明细、改动种数与总克数、最优性结论、求解耗时。
- **批次核查区（页面第 3 节）**：多行文本框粘贴 20～200 行记录，实时显示有效行数；
  「填入示例批次」从服务端取一段与参考同分布的合法文本；「开始核查」后按上述规则展示
  人工复核 / 未检出偏移 / 输入有误三类面板。核查区与求解区各自维护独立的 epoch 与
  AbortController，互不干扰；编辑批次即撤下旧报告，迟到响应不恢复。

## API

| 端点 | 说明 |
| --- | --- |
| `GET /` | 单页网页（含求解区与批次核查区） |
| `GET /api/meta` | 模型规格（树数、深度、种子、阈值、特征名）及漂移核查参数（参考种子、参考条数、置换次数、α） |
| `GET /api/samples` | 经求解器实测的可行 / 无解样例 |
| `POST /api/solve` | 求解；体：`{original, lower, upper, locked}`（各 4 元） |
| `POST /api/drift` | 批次核查；体：`{text: "每行4个整数、总重1000、20～200行"}`。合法返回 `status=review/no_shift` 与统计量、p 值、最差叶节点；非法返回 `status=invalid` + 逐行错误（无 p 值） |
| `GET /api/drift/example` | 一段可直接解析的合法示例批次文本 |

**已实现**

- 试配求解全部既有功能：合成数据 + 固定种子随机森林（5 棵树、深度 ≤ 3）；z3 按原分类器
  真实阈值语义编码；两阶段字典序最优求解；每份建议用原分类器复算；四种结果状态严格区分；
  可行/无解样例（启动时实测）；计算期可修改、修改即撤回、迟到结果不恢复。
- **新增批次适用性核查**（`app/drift.py` + 页面第 3 节 + 两个新 API）：固定种子
  `20241118` 的 1000 条训练外整数克参考配方（启动时按 float32 语义预路由）；逐行输入校验
  （20～200 行、每行 4 个 [0,1000] 整数、总重 1000，错误带行号且不出结论）；五棵树所有
  叶节点占比差最大绝对值统计量；固定种子 `20241119` 的 999 次保持组大小联合置换、
  p=(1+exceed)/1000；p≤0.05 才提示人工复核并展示差异最大树/叶节点与两组占比，否则只报
  未检出偏移且明确不做放行判断；独立 epoch + AbortController 保证编辑即撤下、迟到不恢复，
  与求解区互不影响；`docker compose up --build` 同一镜像同时交付两块功能。

**未验证 / 限制**

- 本环境无 Docker 守护进程，`docker compose up` 未实际执行；Dockerfile 中的每条命令
  （pip 安装相同钉版依赖、uvicorn 启动同一应用，新代码未引入新依赖）已在本机逐一验证，
  compose 文件经 YAML 解析检查，健康检查端点 `/api/meta` 仍可用。
- 前端测试为 DOM 打桩环境，未在真实浏览器中渲染验证样式与交互细节。
- 概率阈值判定含 1e-9 浮点容差（远小于该森林可取概率值的最小间隔约 1e-4），
  用于吸收 float64 求和顺序差异，见 `app/model.py: PROBA_EPS`。
- 参考集与训练数据使用同一 Dirichlet 生成族（同“熟悉范围”、不同种子与不同离散化形式）；
  置换检验的 p 值粒度为 1/1000（999 次置换的固有粒度），在 α=0.05 附近结论可能随粒度波动，
  这是置换检验本身的性质而非实现偏差。
